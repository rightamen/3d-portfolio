# 私聊与关注动态 — 2026-11-07

从干净 main / a994074 接续。用户要求全站独立“消息”和“动态”入口，并确认：
好友可直接聊天，其他人先发消息请求；完成后提交 GitHub 并直接部署。

## 用户流程

- 顶部常驻消息/关注动态图标（各自未读数），头像菜单、手机菜单提供明确文字入口。
- 创作者主页、目录卡片、公开作品作者栏和关注/好友列表均有“发消息”。
- /messages：会话列表、消息请求、新消息搜索；手机点击会话进入聊天，可返回列表。
- 好友立即交流；其他人最多先发送一条请求，接收方接受后双方继续交流。打开会话本身不向对方发送内容。
- 接收方可接受、拒绝或重新接受被拒请求；双方均可屏蔽，只有本人能取消自己的屏蔽。
- 文本消息保留历史、时间与已读状态。Enter 发送、Shift+Enter 换行，输入法组词不误发送。
- 发送失败保留原文与重试键。即使服务器已保存而响应丢失，重试也只返回原消息。
- /following：已关注创作者的新作品、社区帖子、创作者公告与审核通过的资源，按时间排序，可分类和分页。
- 动态未读按用户/类型/实际条目记录；“当前页标为已读”不会误清理后来发布或未展示的内容。
- 发布动态跳转已有个人中心社区编辑；公告可继续通过原个人中心“公告”发布。

本批支持文字私聊，不含附件、语音、群聊或站外推送。会话在可见页面约 3 秒刷新，
列表约 5 秒，顶部计数约 20 秒，动态约 30 秒；页面隐藏/离线时暂停定时刷新，回到页面或联网时恢复。
已有系统通知独立保留，不把私聊写进原订单/审核通知队列。

## 权限与数据

新增三个增量、幂等结构：direct_conversations、direct_messages、following_feed_reads。
既有作品、账户、关注/好友、收藏夹和举报不迁移/重写。
所有接口要求当前 visitor session，GET 为 private/no-store，/api/v1 保留严格 envelope。
不允许调用者通过传入 userId 改变所属账号；第三方不能读、发送、标已读或修改他人会话。
参与者之外（包括普通管理员页面）没有读取私聊正文的入口。

会话使用唯一的规范用户对；开会话按用户/规范对加锁，发消息锁会话并分配单调 seq。
(sender_id,client_id) 唯一约束保障重试幂等，(conversation_id,seq) 唯一约束保障排序。
读位置只能推进且不能超出已有最后消息；仅查看可见且滚到会话末尾时推进已读。
用户换号后旧响应不能进入新账号界面；刷新失败保留当前会话和草稿。
长历史使用排他 before 游标，后台长时间暂停造成的中间缺口也可加载。

新会话目标必须公开、未被管理员隐藏且有 handle；自己不能与自己聊天。
已有会话在对方主页关闭/被隐藏后只给不可用占位，历史保留，不继续向不可用目标发消息。
屏蔽不删除历史，双方都不能继续发送；取消屏蔽只改变自己的屏蔽状态。
限额：正文最多 4000 字符；每天最多发起 20 个新会话；每账号每分钟最多 30 条新消息；
通信写入另有 IP 120 次/分钟限制。幂等重试不重复消耗消息配额。

动态查询实时连接当前 user_follows，只返回公开且未隐藏作者：
作品必须 published，资源必须 approved；社区帖子与资源同时遵守 activity_public。
草稿、未通过资源、取消关注或已关闭公开主页的内容立即从动态/未读计数中撤回。
已读写入再次筛选当时可见条目，伪造 ID 不能提前“读掉”未来发布。
只读到当前用户自己的已读状态，不返回内部作者 ID、邮箱、联系方式或其他用户的关系。

## API

| 路径 | 方法 |
| --- | --- |
| /api/account/communication/summary | GET messagesUnread、requestsUnread、feedUnread |
| /api/account/messages/threads | GET tab=inbox/requests、page、limit；POST {handle} 打开规范会话 |
| /api/account/messages/threads/:id | GET before（排他 seq，默认最近 50 条）；PATCH {action:accept/decline/block/unblock} |
| /api/account/messages/threads/:id/messages | POST {body,clientId} |
| /api/account/messages/threads/:id/read | PUT {seq} |
| /api/account/following-feed | GET kind=work/post/notice/resource（空为全部）、page、limit |
| /api/account/following-feed/read | PUT {items:[{kind,id}]}，1–50 项 |
